# Короткий отчёт по сортировкам строк

## Что измерялось

Были протестированы 6 алгоритмов сортировки строк:

1. Standard Quick Sort
2. Standard Merge Sort
3. String Quick Sort
4. String Merge Sort
5. MSD Radix Sort
6. MSD Radix + Quick Sort

Для каждого алгоритма измерялись:

- среднее время работы в микросекундах;
- среднее количество посимвольных сравнений;
- корректность сортировки.

Все проверки завершились успешно: во всех строках файла `results.csv` значение `sorted` равно `yes`.

## Случайные массивы

На случайных массивах быстрее всего работают `MSD Radix + Quick Sort`, `MSD Radix Sort` и `String Quick Sort`.

Обычный `Quick Sort` работает заметно медленнее, потому что он много раз сравнивает строки с начала. При сравнении строк это дорого: если первые символы совпадают, приходится идти дальше по строке.

`Merge Sort` работает стабильнее, чем обычный `Quick Sort`, но медленнее специализированных строковых алгоритмов.

## Обратно отсортированные массивы

Здесь хуже всего показал себя обычный `Quick Sort`.

Причина простая: в реализации опорный элемент берётся из начала фрагмента. Для обратно отсортированного массива это неудачный выбор, поэтому разбиения получаются плохими, и алгоритм делает слишком много сравнений.

Лучший результат по времени здесь показывает `MSD Radix Sort`.

## Почти отсортированные массивы

На почти отсортированных данных снова хорошо работают radix-алгоритмы.

Обычный `Quick Sort` всё ещё сильно проигрывает, потому что порядок данных для него может быть неудачным.

`Merge Sort` и `String Merge Sort` идут почти одинаково, потому что текущая реализация `String Merge Sort` фактически сравнивает строки посимвольно так же, как обычный merge sort.

## Массивы с одинаковым префиксом

На строках с общим префиксом лучший результат показал `String Quick Sort`.

Это логично: строковые алгоритмы умеют учитывать уже совпавшие символы и не начинают сравнение каждый раз полностью с нуля.

Обычные сортировки здесь проигрывают, потому что при каждом сравнении снова проходят общий префикс.

## Почему у Radix Sort меньше сравнений

`MSD Radix Sort` не сравнивает строки целиком друг с другом. Он распределяет строки по символам: сначала по первому, потом внутри групп по второму и так далее.

Поэтому количество посимвольных обращений обычно меньше, чем у обычных сортировок на сравнениях.

## Итог

Специализированные алгоритмы сортировки строк в среднем работают лучше обычных сортировок.

Лучшие результаты:

- для случайных массивов: `MSD Radix + Quick Sort`;
- для обратно отсортированных массивов: `MSD Radix Sort`;
- для почти отсортированных массивов: `MSD Radix + Quick Sort`;
- для строк с одинаковым префиксом: `String Quick Sort`.

Главный вывод: при сортировке строк важно учитывать посимвольную структуру строк. Обычная оценка `O(n log n)` не полностью отражает реальную стоимость, потому что каждое сравнение строк может занимать не `O(1)`, а до `O(m)`, где `m` — длина строки.
